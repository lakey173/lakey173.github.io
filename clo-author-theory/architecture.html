Worker-Critic Loop

Every creator agent is paired with a critic. The loop runs up to 3 rounds:

Worker produces artifact
    │
    ▼
Critic reviews → Score ≥ 80?
    │                    │
    NO                  YES
    │                    │
    ▼                    ▼
Worker fixes         ✓ Approved
(Round 2)
    │
    ▼
Critic re-reviews → Score ≥ 80?
    │                    │
    NO                  YES
    │                    │
    ▼                    ▼
Worker fixes         ✓ Approved
(Round 3)
    │
    ▼
Critic re-reviews → Score ≥ 80?
    │                    │
    NO                  YES
    │                    │
    ▼                    ▼
ESCALATE             ✓ Approved

Separation of Powers: Critics never create artifacts. Creators never self-score. A critic who fixes its own findings has incentive to find only fixable issues.

Targeted re-entry: A referee says "the existence proof has a gap." The Orchestrator routes back to Derivation-Engineer only (not through the full pipeline), theory-coder-critic reviews, Writer updates the proof sketch.

Scoring Protocol

Weighted aggregate gates submission:

Component Weight Source
Literature coverage10%Librarian-Critic
Model setup25%Model-Critic
Proofs / derivations25%Theory-Coder-Critic (avg of proofs + code)
Paper quality20%Avg of Domain-Referee + Theory-Referee
Manuscript polish10%Writer-Critic
Compilation / verification10%Verifier (pass/fail → 0 or 100)

Per-component minimum: No component below 80 for submission. A polished manuscript cannot compensate for an incorrect proof.

Missing components: If a component hasn't been scored, it's excluded and remaining weights renormalized.

Gate Overall Score Per-Component Min

Submission≥ 95≥ 80 per component

Parallel Dispatch

Independent phases run concurrently:

  • Literature (Librarian) and Modeling Landscape (Literature-Explorer) run in parallel
  • Derivation-Engineer and Theory-Coder run in parallel (both from the same model memo)
  • Presentation can run parallel with Peer Review
  • /review --all dispatches all critics in parallel

Plan-First Protocol

For non-trivial tasks:

  1. Enter plan mode
  2. Check MEMORY.md for relevant learnings
  3. Draft plan (what changes, which files, in what order)
  4. Save to quality_reports/plans/YYYY-MM-DD_description.md
  5. Present to user for approval
  6. Execute via orchestrator

Plans survive context compression — they're saved to disk.

Working Paper Format

All papers follow the standard economics theory working paper format:

  • \documentclass[12pt]{article} with 1-inch margins
  • \onehalfspacing (1.5× line spacing — theory standard)
  • amsthm theorem environments with shared counter (except Assumptions)
  • cleveref for auto-detected cross-references
  • biblatex + biber (not natbib + bibtex)
  • hyperref loaded last
  • Appendix with \numberwithin{theorem}{section} for Proposition A.1, Lemma B.1, etc.

See the rules files for the complete reference preamble.

Constitutional Governance

Before committing, ask: would another theory researcher forking this repo benefit from this change?

  • Yes → commit (workflow patterns, skills, agents, rules)
  • No → keep local in .claude/state/ (machine paths, API keys, institutional details)
