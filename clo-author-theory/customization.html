Customization Guide

Tailor clo-author-theory to your research

The 6 Configuration Layers

From broadest to most specific:

1. CLAUDE.md (Project Constitution)

The root CLAUDE.md file (~120 lines) is the project constitution. It defines:

  • Project name, institution, field
  • Folder structure
  • Compilation commands
  • Quality thresholds
  • Skills quick reference
  • Beamer custom environments
  • Current project state tracker

Fill in the [BRACKETED PLACEHOLDERS] when you first fork:

Project: [YOUR PROJECT NAME]
Institution: [YOUR INSTITUTION]
Field: [YOUR FIELD — e.g., Industrial Organization, Contract Theory]

3. Agents (18 definitions)

Each .claude/agents/*.md file defines one agent:

  • Role and responsibilities
  • Tools available (Read, Write, Edit, Bash, Grep, Glob, WebSearch, WebFetch)
  • Model assignment (Opus for complex reasoning, Sonnet for speed)
  • Scoring rubric (for critics)
  • Escalation target

You can customize:

  • Scoring rubrics — adjust deduction points for your field's priorities
  • Model assignments — change which agents use Opus vs. Sonnet
  • Escalation routing — change who handles 3-strike failures

4. Skills (11 commands)

Each .claude/skills/*/SKILL.md defines a slash command. Skills dispatch agents and enforce workflows. You generally don't need to modify these unless adding new commands.

5. References (Domain Profile + Journal Profiles)

Domain Profile (domain-profile.md)

The domain profile calibrates all agents to your field. Key sections:

  • Field: e.g., "Industrial Organization — Applied Theory"
  • Modeling approaches: What techniques your field uses (signaling, screening, mechanism design, etc.)
  • Solution concepts: PBE, Nash, dominant strategy, etc.
  • Notation conventions: What symbols are standard in your subfield
  • Seminal references: The 5–10 papers every paper in your area must cite
  • Quality tolerance thresholds: Numerical precision for computation

Run /discover interview [topic] to auto-populate, or fill manually.

Journal Profiles (journal-profiles.md)

18 theory journal profiles pre-configured:

  • Top 5 generals (theory track): Econometrica, AER, QJE, JPE, REStud
  • Theory-specific: Theoretical Economics, JET, GEB, RAND, AEJ:Micro
  • Field journals: JEEA, Management Science (theory), J. Finance (theory), J. Int'l Econ, J. Public Econ, J. Labor Econ, European Econ Rev, Canadian J. Econ

Each profile includes: scope, acceptance rate, theory bar, page limits, referee dispositions, and what they look for.

Add your own journal profiles following the existing format.

Domain Profile Deep Dive

The domain profile is the most important customization. It tells every agent what field you're in and how that field works.

Example for Industrial Organization:

## Field
Industrial Organization — Applied Theory

## Modeling Approaches
- Cournot/Bertrand competition
- Vertical differentiation
- Entry deterrence
- Mechanism design for auctions
- Information design

## Solution Concepts
- Nash Equilibrium (simultaneous games)
- Subgame Perfect Equilibrium (sequential games)
- Perfect Bayesian Equilibrium (signaling/screening)
- Bayesian Nash Equilibrium (incomplete information)

## Notation Conventions
- Firms indexed by i ∈ {1, ..., n}
- Quantities: q_i, Prices: p_i
- Costs: c_i or C(q_i)
- Consumer surplus: CS, Producer surplus: PS
- Welfare: W = CS + PS

## Seminal References
- Tirole (1988) — The Theory of Industrial Organization
- Fudenberg and Tirole (1991) — Game Theory
- Mas-Colell, Whinston, Green (1995) — Microeconomic Theory

Customizing the Editor's Referee Pool

The Editor assigns referees with dispositions. You can customize:

6 Dispositions:

  1. Generality Hawk — wants results to hold beyond specific functional forms
  2. Tractability Minimalist — wants simpler models
  3. Novelty Skeptic — skeptical that results are genuinely new
  4. Micro-Foundations Purist — wants every assumption micro-founded
  5. Policy Oriented — wants policy implications
  6. Professional Skeptic — challenges everything

Pet Peeves (18 critical + 18 constructive):

Add field-specific pet peeves to the editor agent definition. Examples:

  • Critical: "Claims general result but only proves for linear demand"
  • Constructive: "Suggests extending to asymmetric firms"

Memory System

4 persistent layers:

Layer Location Survives
Auto-memory~/.claude/projects/[project]/memory/MEMORY.mdAll sessions
Session logsquality_reports/session_logs/Context compression
Plans on diskquality_reports/plans/Context compression
Research journalquality_reports/research_journal.mdAll sessions

What gets saved automatically:

  • Corrections you make (MEMORY.md)
  • Workflow preferences
  • Architecture decisions
  • Solutions to recurring problems

Context survival: Before compression, the pre-compact hook reminds Claude to save important state. After compression, Claude reads MEMORY.md + latest plan + git log to resume.

Adding a New Agent

Create the agent definition

Create .claude/agents/your-agent.md with: description of role, available tools, model assignment (optional), responsibilities, and scoring rubric (if critic).

Register the pairing

Update .claude/rules/agents.md with the worker-critic pairing.

Wire into a skill

Update the relevant skill to dispatch the new agent.

Update quality scoring

Update quality.md if the agent contributes to the aggregate score.

Adding a New Skill

Create the skill definition

Create .claude/skills/your-skill/SKILL.md with: command syntax, description, arguments and modes, workflow steps, agents to dispatch, and output locations.

Register in CLAUDE.md

Add the new command to the skills reference table in CLAUDE.md.

Add to quick reference

Add the command to WORKFLOW_QUICK_REF.md.
